# Conditional M209 pair fitness

`m209_pair_features(text, tables)` returns six fitness scores in lag order17,19,21,23,25,26. Its only language input is `tables["english"]`, a26-entry probability vector from the caller's training split. It uses the fixed public LP pin patterns and lug settings already recorded in the [M209 helper](../engine/solvers/m209.py) and its [supplied-key certificate](../engine/data/m209_certificate.json). The cited construction and mathematical reference are [Bouchaudy's M209 example](http://www.jfbouch.fr/crypto/m209/WORK/index.html) and [mathematical page](http://www.jfbouch.fr/crypto/m209/WORK/mathematical.html). The source server returned502 during the new feature review on2026-10-03; the constants and existing certificate are reused without a new historical-source claim.

The features assume those internal settings and unknown external wheel phases sampled independently and uniformly. They do not describe arbitrary pin/lug settings, recover an external key, or decipher a historical message. They are a new bounded feature composition in this repository, with no priority claim.

For each wheel and lag, count its four possible active-pin pairs across all cyclic starting phases. Multiplying six independent wheel-pair distributions gives4096 active-mask-pair probabilities. The lug rule converts each mask pair into a displacement pair modulo26. Fixed building offsets only relabel the uniform phases and consequently do not change this marginal law. This averages over the external phases algebraically, without enumerating the full101,405,850 phase settings or storing sample keys.

Using the existing machine formula `C =25+K-P mod26`, combine each displacement-pair probability with two independent plaintext letters drawn from the training unigram. This creates a26 by26 ciphertext-pair probability table for each lag. `m209_pair_tables(english)` returns its immutable log tables. The scores average the log probability of observed lagged ciphertext pairs and subtract the log probability of a uniform independent pair. A missing lag pair returns zero evidence.

These are composite fitness values. Overlapping pairs are dependent, and actual prose is richer than an independent unigram model. A score is not a calibrated family probability, an exact complete-message likelihood, or evidence of a unique plaintext. Early development controls show overlapping Enigma and M209 score ranges; model selection must use independent evaluation rather than treating these values as a proof of class membership.

The implementation uses the standard library. It accepts16..8192 normalized A-Z letters and at most8192 raw characters. Unicode letters are rejected. The training vector must contain finite probabilities in1e-100..1 summing to one within1e-6; normalization removes minor rounding differences. Pair tables cache at most four training vectors, and the six fixed displacement distributions cache independently. Each feature call reads at most six times the bounded ciphertext length.

Tests compare the phase marginal against exhaustive external settings of a small two-wheel construction, verify the two-letter Beaufort formula with known displacements, check probability normalization and expected log-fit signs, require neutral features under uniform training statistics, and reject malformed or unrepresentable inputs. Those controls verify the feature mathematics and bounds, rather than an unknown-key M209 solver.
